# قالب مواقع مكاتب المحاماة

موقع ثابت من صفحة واحدة، محتواه يُدار من لوحة عربية (Pages CMS)، ويُحفظ في GitHub، ويُنشر تلقائياً على Cloudflare Pages. لا قاعدة بيانات ولا خادم.

## كيف يعمل

```
العميل يعدّل في لوحة الإدارة  →  Pages CMS يحفظ commit في GitHub
→  Cloudflare Pages يبني الموقع (node build.js)  →  الموقع يتحدّث خلال دقيقة تقريباً
```

| المسار | الوظيفة | من يعدّله |
|---|---|---|
| `content/*.json` | كل نصوص الموقع وبياناته وألوانه | العميل من لوحة الإدارة |
| `media/` | الصور المرفوعة (شعار، فريق، خلفيات) | العميل من لوحة الإدارة |
| `.pages.yml` | تعريف حقول لوحة الإدارة | أنت فقط |
| `src/` و `build.js` | التصميم والقالب ومولّد الصفحة | أنت فقط |
| `dist/` | الناتج الجاهز للنشر (يُولَّد تلقائياً ولا يُرفع إلى GitHub) | — |

المعاينة على جهازك (تحتاج Node.js فقط، بلا أي تثبيت):

```bash
node build.js --serve
```

ثم افتح `http://localhost:5173`.

## ما الذي يتحكم به العميل من اللوحة

1. **الهوية والألوان**: الاسم، الوصف، الشعار، أيقونة المتصفح، أربعة ألوان (تُشتق منها بقية الدرجات تلقائياً)، رقم الترخيص.
2. **الواجهة الرئيسية**: العنوان، الوصف، نصوص الأزرار، صورة الخلفية، نقاط الثقة، بطاقة الخطوات.
3. **الإحصائيات**، 4. **من نحن**، 5. **الخدمات** (إضافة/حذف/ترتيب)، 6. **لماذا نحن**.
7. **فريق العمل** (أسماء، مسميات، نبذات، صور)، 8. **آراء العملاء**.
9. **التواصل**: واتساب، هاتف، بريد، عنوان، رابط الخرائط، ساعات العمل، سبعة حسابات تواصل اجتماعي.
10. **SEO**: العنوان، الوصف، الكلمات المفتاحية، رابط الموقع، صورة المشاركة، رمز تحقق Google، خيار الإخفاء عن محركات البحث.

الأقسام الاختيارية (الإحصائيات، الفريق، آراء العملاء) لها مفتاح إظهار/إخفاء، وروابطها تختفي من القائمة معها.

## أولاً: نقل موقع roeya.pages.dev إلى GitHub دون توقف

مشروعك الحالي من نوع «الرفع المباشر»، و Cloudflare لا يسمح بتحويله إلى Git integration لاحقاً. لذلك نُبقي المشروع نفسه ونجعل GitHub Actions هو من يرفع إليه. الرابط `roeya.pages.dev` لا يتغير، والنسخة الحالية تبقى تعمل إلى أن ينجح أول نشر جديد.

### 1. أنشئ المستودع وارفع الملفات

أنشئ مستودعاً **خاصاً (Private)** فارغاً على GitHub من `https://github.com/new` (بدون README)، وليكن اسمه `roeya-site`. ثم من داخل مجلد المشروع:

```bash
git init -b main
```

```bash
git add .
```

```bash
git commit -m "قالب موقع المحاماة مع نظام إدارة المحتوى"
```

```bash
git remote add origin https://github.com/USERNAME/roeya-site.git
```

```bash
git push -u origin main
```

استبدل `USERNAME` باسم حسابك. لن يُنشر شيء بعد، لأن النشر متوقف إلى أن تضيف المتغير في الخطوة 3.

### 2. أنشئ رمز Cloudflare

في لوحة Cloudflare: **My Profile → API Tokens → Create Token → Custom token**، بصلاحية واحدة فقط: **Account → Cloudflare Pages → Edit**. انسخ الرمز، وانسخ **Account ID** من صفحة Workers & Pages.

### 3. أضف الأسرار في GitHub

في المستودع: **Settings → Secrets and variables → Actions**

| النوع | الاسم | القيمة |
|---|---|---|
| Secret | `CLOUDFLARE_API_TOKEN` | الرمز من الخطوة 2 |
| Secret | `CLOUDFLARE_ACCOUNT_ID` | معرّف الحساب |
| Variable | `CF_PAGES_PROJECT` | `roeya` |

### 4. شغّل أول نشر وتحقق

في تبويب **Actions** اختر **Deploy to Cloudflare Pages → Run workflow**. بعد نجاحه افتح مشروع `roeya` في Cloudflare وتأكد أن آخر نشر مصنّف **Production**، ثم افتح `roeya.pages.dev`.

- إن ظهر النشر على أنه **Preview**: فرع الإنتاج في المشروع ليس `main`. غيّر `--branch=main` في `.github/workflows/deploy.yml` إلى اسم فرع الإنتاج الظاهر في إعدادات المشروع.
- إن ظهر خطأ في الموقع: من **Deployments** في Cloudflare اضغط على النشر السابق ثم **Rollback** فيعود الموقع القديم فوراً.

> قبل أول نشر راجع `content/team.json`: قسم الفريق يحوي أسماء نموذجية («اسم المحامي»). عدّلها أو اجعل `show` يساوي `false`.

## ثانياً: ربط لوحة الإدارة (Pages CMS)

1. افتح `https://app.pagescms.org` وسجّل الدخول بحساب GitHub.
2. ثبّت تطبيق Pages CMS على حسابك، واختر **Only select repositories** ثم حدّد مستودعات العملاء فقط.
3. افتح المستودع. ستظهر الأقسام العشرة بالعربية لأن ملف `.pages.yml` موجود مسبقاً.
4. عدّل أي حقل واضغط حفظ. سيظهر commit جديد في GitHub ويبدأ النشر تلقائياً.

الرابط `/admin` في أي موقع من القالب يحوّل إلى لوحة الإدارة.

Pages CMS مفتوح المصدر، ونسخته المستضافة مجانية وقت كتابة هذا الدليل. شروط الاستخدام غير موثّقة في صفحاته، فتحقق منها قبل الاعتماد عليه مع عشرات العملاء؛ والبديل عند الحاجة استضافته ذاتياً.

## ثالثاً: إنشاء موقع لعميل جديد

اجعل مستودعك قالباً مرة واحدة: **Settings → General → Template repository**. ثم لكل عميل:

1. **انسخ القالب**: من صفحة المستودع اضغط **Use this template → Create a new repository**، واجعله **خاصاً** باسم العميل (مثل `client-alnoor`).
2. **أنشئ مشروع Cloudflare**: **Workers & Pages → Create → Pages → Connect to Git**، اختر مستودع العميل، ثم:
   - Framework preset: `None`
   - Build command: `node build.js`
   - Build output directory: `dist`

   لا تضف المتغير `CF_PAGES_PROJECT` في هذا المستودع، حتى لا يُنشر الموقع مرتين.
3. **اربط النطاق**: من المشروع **Custom domains → Set up a domain**.
4. **أضف المستودع** إلى قائمة المستودعات المسموحة لتطبيق Pages CMS في GitHub (Settings → Applications → Pages CMS → Configure).
5. **خصّص المحتوى**: افتح المستودع في Pages CMS وأدخل بيانات العميل، وحدّث «رابط الموقع» في قسم SEO.

كل عميل له مستودع ومشروع ونطاق ومحتوى وصلاحيات مستقلة، والكود واحد.

### تحديث القالب لدى عميل قائم

لأن المحتوى (`content/` و `media/`) مفصول عن الكود، يمكن سحب تحسينات القالب دون المساس بمحتوى العميل:

```bash
git remote add template https://github.com/USERNAME/roeya-site.git
```

```bash
git fetch template
```

```bash
git checkout template/main -- src build.js package.json .pages.yml .github
```

```bash
git commit -m "تحديث القالب"
```

هذا يستبدل ملفات الكود فقط ويترك `content/` و `media/` كما هي. عاين النتيجة بـ `node build.js --serve` قبل `git push`.

## رابعاً: تسليم لوحة الإدارة للعميل بأمان

1. في Pages CMS افتح مستودع العميل وادعُ العميل ببريده الإلكتروني من قسم المتعاونين (Collaborators). لا يحتاج حساب GitHub.
2. أرسل له رابط اللوحة `https://app.pagescms.org` (أو `موقعه/admin`).

ما يستطيعه العميل المدعو: تعديل المحتوى والصور في مستودعه فقط.
ما لا يستطيعه: تعديل `.pages.yml`، دعوة آخرين، رؤية مستودعات عملاء آخرين، أو الوصول إلى GitHub و Cloudflare.

قواعد الأمان:

- **لا أسرار في الملفات**: الموقع لا يحوي أي مفتاح. رمز Cloudflare محفوظ في GitHub Secrets فقط، ولوحة الإدارة تعمل بتسجيل دخول المستخدم.
- **المستودعات تبقى في حسابك** وخاصة. لا تضف العميل كـ Collaborator في GitHub نفسه.
- **سحب الصلاحية**: احذف بريد العميل من Collaborators في Pages CMS.
- **التراجع عن خطأ**: كل حفظ commit مستقل، فيمكن استرجاع أي نسخة من سجل GitHub، أو عمل Rollback من Cloudflare.
- **إن أخطأ العميل في البيانات** فالبناء يتجاهل القيم غير الصالحة (لون خاطئ، رابط غير آمن). وإن فشل البناء كلياً يبقى الموقع على آخر نسخة سليمة.
- فعّل المصادقة الثنائية على حسابي GitHub و Cloudflare.
